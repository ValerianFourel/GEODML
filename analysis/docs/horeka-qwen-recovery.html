01 / PREPARE

Recover saved work and freeze the missing cells

Run this once. It fetches the pinned helper and submits one CPU reconciliation job. That job seals recoverable results from ended writers, completes valid saved responses, releases only confirmed stale claims, and creates a separate recovery division.

Completed cells and terminal failures are excluded from inference. Unknown ownership, invalid evidence and other unresolved cases remain in the report. The original qwen-bouts/CURRENT and old submissions stay in place.

02 / RELAUNCH

Submit the next recovery job

Each invocation submits at most one new job from the frozen list. Repeat after checking Status, until the helper prints FINITE_SWEEP_SUBMITTED. This is a finite sweep; it does not add replacement jobs or extend the budget when an allocation ends.

The worker uses the same Qwen model, revision, prompts, seeds, settings and task identities. Its shared ledger skips cells already completed by another recovery worker. It takes eligible work from its assigned list and spillover, with checkpoints before the actual Slurm end time.

Admission checks all your active allocations, including interactive sessions. It requires fewer than five active allocations, no unheld pending allocation, at least ten minutes since the latest observed start, and fresh byte/inode quota evidence. If blocked, wait on the login host and repeat this command. Keep existing allocations and their shells open.

A confirmed sbatch refusal can be retried with the same command because no allocation exists. A missing or ambiguous submission receipt stops further jobs until it is reconciled. HF-registered work or newly published selected cells also stop legacy admission.
